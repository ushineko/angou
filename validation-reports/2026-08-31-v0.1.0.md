# Validation report — angou v0.1.0

**Date**: 2026-08-31
**Commit**: the release commit bumping `VERSION` and `README.md` to 0.1.0
**Spec**: [001 — container format, key model, store layout, and bootstrap](../specs/001-angou-format-keying-and-store.md)
**Scope**: the command line. The desktop navigator is not started.

---

## Summary

The CLI is complete. All seventeen subcommands of spec 001 R6.4 are implemented, and
all 56 acceptance criteria in that spec are met, two of them in a narrower form than
their wording suggests (recorded below and in the spec itself). This is the first
release; there are no existing consumers and nothing to migrate.

---

## Phase 3 — Tests

| Gate | Result |
|---|---|
| `make test` (unit, `-race`) | pass — 6 packages |
| `make e2e` | pass — 70 tests |
| `make e2e-keyring` | not run in this cycle; see below |
| `make e2e-container` | not implemented |
| `make shellcheck` | pass |

End-to-end tests build the binary with the `build-static` flags and drive it as a
subprocess against throwaway stores, at the parameters users actually get. There is no
configuration that only the tests exercise: the lowered-KDF lever that once existed was
removed when the parameter change made it unnecessary.

**`make e2e-keyring` was not run.** It drives a live `kwalletd6` and therefore operates
the wallet holding the developer's real secrets. KWallet has no non-interactive way to
create a wallet of the suite's own — opening one that does not exist raises a desktop
dialog and blocks — so those tests are gated behind their own target and need a human
present. They passed when last run manually. `make e2e` does not touch the wallet at
all.

## Phase 4 — Code quality

`make lint` reports 0 issues at the pinned `golangci-lint v2.12.2`, with the
`GOTOOLCHAIN` pinned from `go.mod`.

No dead code, no duplicated logic blocks, and no function over 50 lines was found in the
release-cycle pass. Two structural notes:

- Platform-specific code is split by build constraint (`keyring_linux.go`,
  `keyring_darwin.go`, `peer_linux.go`, `memory_linux.go`), so a macOS backend is a new
  file rather than a refactor.
- `wrapcheck` is configured to ignore errors crossing this module's own packages.
  Wrapping them again produced messages of the form "open store: open store: ...".

## Phase 5 — Security review

**Dependency scan.** `govulncheck` (Go 1.26.5): **no vulnerabilities**, 0 affecting this
code. 21 module dependencies. `github.com/cloudflare/circl` was raised from v1.6.2 to
v1.6.3 during development to clear GO-2026-4550.

**Secrets.** No key material, passphrase, or store content is committed. The scan finds
no private-key blocks or credential-shaped assignments outside test fixtures, and the
test fixtures use deliberately inert strings. `.gitignore` blocks `*.angou`,
`store.angou`, `index.angou`, and `bootstrap/` as a backstop rather than as the control.

**Log paths.** A test drives every command at `--verbose` and asserts that neither the
recovery passphrase nor the plaintext nor the plaintext's digest appears in stderr. The
digest is excluded deliberately: for a low-entropy secret it is a reusable oracle.

**Review rounds.** Two independent reviews (Codex) produced twelve findings across the
implementation passes. Eleven are fixed and carry regression tests. The twelfth — that
KWallet tests should use a wallet dedicated to the run — cannot be satisfied as stated
and is documented in the test file with its residual exposure: an inert entry left in the
developer's wallet if a run is killed outright.

Findings worth recording because the failure would have been silent:

- The version floor was enforced only in `bootstrap`, leaving a replayed older signed
  binary able to read and write every blob. Now enforced on every unlock.
- `prune --bundles` kept the current bundle by filename, which after a rotation
  interrupted between the two file swaps is the one that does *not* open the store.
- `prune --orphans` deleted blobs failing the name binding, destroying both a live
  secret and the evidence of tampering.
- `rekey --identity` did not confirm the new recovery passphrase before deleting the old
  blobs, making a typo unrecoverable.
- `clone` followed symlinks found in the store and accepted a destination inside the
  source.

Three further defects were found by using the tool rather than by review, and are worth
recording because each was invisible to the suite:

- `enc` refused an absolute path, so `angou enc ~/.secrets.env` — the most natural
  invocation there is — did not work.
- `--ttl` accepted only Go's duration syntax, which has no days or weeks and rejects a
  bare number, so `3600`, `1d`, `1w` and `99999` were all errors.
- Nothing anywhere told a new user to run `angou bootstrap`, so the intended fast path
  was undiscoverable and every command asked for the recovery passphrase. `init`,
  `install.sh`, and the recovery-passphrase path itself now say so. The hint is gated on
  a non-blocking check that kwalletd is running: an earlier version of it probed by
  opening the wallet, which can raise a desktop dialog and hang the command it was
  trying to help.

**Permissions.** Everything holding key material is 0600, and its directories 0700: the
local key, the key bundle, blobs, the store metadata, and the agent socket.

**Stated non-guarantees.** Three claims are deliberately bounded in code, help text, and
documentation, and tests assert the wording holds:

- The agent's socket mode excludes other users and is not a boundary against processes
  running as the same user (R-10).
- The installer's self-check is detection after execution, not proof the script that ran
  was genuine (R5.8.2, R5.8.3).
- Buffer zeroing is best-effort; Go's garbage collector may relocate a secret first
  (R-2).

## Phase 5.5 — Release safety

**Rollback**: remove `~/.local/bin/angou` and the installed MIME, magic, and desktop
entries. There are no existing consumers and no migration. Stores written by this
version are readable by it; the `ANGOU1` magic exists so a future format change is
detected rather than misparsed.

**Additive**: this is the first release. Nothing is removed or changed for anyone.

**Data at risk**: none. No command in this release rewrites a user's store except at
explicit request, and the two that do (`rekey --identity`, `passwd`) stage their work and
verify it before touching anything live.

## Acceptance criteria

56 of 56 met. Two are met more narrowly than their wording suggests, recorded here and
in the spec rather than glossed:

- The bare-machine bootstrap is exercised in a stripped environment — empty environment
  block, throwaway `HOME`, nothing of angou's on `PATH`, system `gpg` — rather than in a
  container.
- `make build-static` is confirmed statically linked by `ldd` and `file`. Running it in a
  `scratch` container is not exercised.

Three requirements were found to be unimplementable as written during the work, and the
spec was corrected rather than the claim quietly weakened:

- **R5.4.3** — `bootstrap.sh` cannot enforce the version floor, because the floor is
  inside the encrypted store and a plaintext installer has no key for it. Enforcement is
  split between the installer ("newest present") and the tool (the real floor).
- **R5.5.1** — the installer's self-check verifies a detached signature over itself
  rather than the digest recorded in the store, for the same reason. This is stronger
  from that position: altering the script requires the offline release key.
- **R6.5.1** — the agent socket path is bounded by `sockaddr_un.sun_path`; the limit is
  checked where it can be explained.

## Known gaps

- `make e2e-container` is a target with no implementation.
- The macOS Keychain keyring backend is deferred; R2.5 covers the interim.
- The desktop navigator is not started.
- Freshness and anti-rollback for the store itself remain accepted and documented
  (R-9) rather than built.
