# Validation report — angou v0.1.3

**Date**: 2026-09-01
**Spec**: [001](../specs/001-angou-format-keying-and-store.md)
**Scope**: three user-facing additions. One envelope field is added; no key model,
container format, or store layout change.

---

## Summary

Three requested features: scanning a directory for credentials, restoring a file to
where it was encrypted from, and a listing worth reading. All three are exercised
end to end.

The envelope gains an `origin` field. Older blobs simply lack it and behave as before,
and `rekey --identity` carries it through a re-encryption.

## Phase 4 — Code quality

`make lint` reports 0 issues. `ls` moved from an inline listing to its own file with the
formatting helpers beside it; the previous `--long` flag is kept as a hidden no-op
rather than removed, since the detailed output it asked for is now the default.

## Phase 5 — Security review

**Dependency scan.** `govulncheck`: no vulnerabilities. No new dependencies.

**Acting on a path from the store.** `dec` restoring to a recorded location means the
store names a destination on this machine. That is defensible only because payloads are
signed (R1.7): forging the destination means forging the signature, so write access to
the store does not buy a write anywhere on disk. The R-9 replay case still applies and
yields an older genuine path. The destination is shown and confirmed, a non-absolute
one is refused, and a symlink or non-regular file at the destination is refused rather
than written through.

**Permissions on restore.** `os.WriteFile` applies its mode only when creating, so
replacing an existing file kept that file's permissions. A `0600` key restored over a
`0644` file would have stayed world-readable. The mode is now set explicitly after the
write, which also covers the umask widening it on creation.

**Silence is not consent.** `confirm` takes the default when there is no terminal, which
made `enc --all` sweep a whole directory into the store unattended — the default for
"encrypt this?" being yes. It now refuses without `--auto` and says so. The questions
whose default is "no" are the destructive ones, so the same rule leaves `--restore`
declining to replace an existing file unless told.

**Scanner scope.** The scan reports rather than acts, does not follow symlinks, bounds
file size and depth, and skips directories that would drown a real finding in vendored
copies. It is documented as a convenience and not a control, and an empty result is
reported as "the scan found nothing", never as "there is nothing here".

**Listing.** `ls --raw` needs no passphrase and reads only directory entries, which are
what anyone holding the store already sees. It states in the same breath what the keyed
naming hides and what it does not.

## Phase 5.5 — Release safety

**Rollback**: revert the release commit. A store written by this version is readable by
0.1.2, which ignores the unknown `origin` field; a store written by 0.1.2 works here and
simply has no origin to restore to, so `dec` writes to stdout as it always did.

**Behaviour change**: `angou ls` prints a table where it printed paths. Scripts that
parsed it need `--names`, which is why that form exists.

## Known gaps

- The scanner's pattern list is a judgement call and will need adding to. It is not a
  security control and is documented as one thing it must not be mistaken for.
- Restore is verified against recorded absolute paths from another machine's home
  directory. A store carried between machines with different usernames restores to the
  *original* path, which may not exist here; `-o` covers that and the destination is
  always shown first.
- gnome-keyring remains untested (carried from 0.1.2).
- `make e2e-container` is a target with no implementation.
