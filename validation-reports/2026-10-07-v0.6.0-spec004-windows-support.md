### Phase 4: Code Quality

- `make lint` (golangci-lint v2.12.2): 0 issues on Windows and on Linux.
- The first Windows lint run found 8 issues in Windows-only files, now fixed:
  - `keyring_windows.go`: two errors from `x/sys/windows` returned unwrapped;
    now wrapped with `%w`, so `errors.Is(err, errNotFound)` still holds.
  - `keyring_windows.go`: six `unsafe.Pointer` uses (G103) annotated with the

    so staticcheck does not read the stub as a pure call (SA4017).
- `install-lint` did not work on a stock MSYS2 (no `unzip`); it now falls back
  to `bsdtar` or `System32\tar.exe`. Spec R5.4 updated.
- Dead code, duplication: none found.
- Status: ✓ PASSED

### Phase 5: Security Review

- Dependencies: `govulncheck` (on njv-cachyos) reports 0 vulnerabilities
  affecting the code. One in a required module is not reachable:
  GO-2026-5932, the deprecated `golang.org/x/crypto/openpgp` package, with no fix
  available. angou uses `ProtonMail/go-crypto`.
- Secret handling: the Credential Manager copy of the passphrase is zeroed
  before `CredFree`; the caller zeroes its own copy, as on other platforms. No
  passphrase reaches a log (`TestVerboseDisclosesNoSecret` passes on both).
- Subprocesses: none added to the CLI. The Windows CLI is CGO-free and the
  static-binary e2e test checks every imported DLL is in System32.
- Access control: the agent is refused on Windows rather than run without a
  peer check. Credential Manager entries persist `LOCAL_MACHINE`, not
  `ENTERPRISE`, so they do not roam.
- File operations: extraction on Windows checks for a symlink before opening.
  The check and the open are two steps (TOCTOU), stated in code, spec R1.2 and
  the changelog. A file encrypted on Windows records `0600`/`0400`, not the
  `0666` Go reports there.
- Installer integrity: `bootstrap.ps1` is signed by the release key and
  recorded in store metadata; its self-check is described as detection after
  execution, the same wording as `bootstrap.sh` (spec 001 R5.8.2).
- No secrets in the diff: checked for armored private keys and passphrase
  literals before committing.
- Status: ✓ PASSED

### Phase 5.5: Release Safety

- Change type: code, plus an additive store-metadata field.
- `bootstrap_ps1_sha256` is optional. A store without it reads as "nothing
  recorded", and an older angou that drops it on rewrite loses only that record.
  `bootstrap.ps1` beside `bootstrap.sh` is ignored by older versions.
- Rollback: revert the commit. A store already released with `bootstrap.ps1` and
  Windows binaries stays usable by 0.5.x on Linux and macOS.
- Rollout: rehearsal release into a copy of the store first, then the real
  store, then bootstrap a Windows machine from it.
- Status: ✓ PASSED
