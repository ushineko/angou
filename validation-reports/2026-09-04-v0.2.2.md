# Validation report — angou v0.2.2

**Date**: 2026-09-04
**Spec**: [002](../specs/002-desktop-gui.md)
**Scope**: a file chooser beside the GUI's path fields, the crash that shipped in the
first version of it, and one heading reworded. No CLI, container format, key model, or
store layout change.

---

## Summary

Every path in the GUI was typed by hand: the directory to scan, the file to encrypt,
where to extract, where to clone, which store to open. Each of those fields now carries a
Browse button that opens Fyne's chooser, starting at whatever the field already holds, or
its parent, or the home directory. The field stays editable, so a path the chooser will
not show can still be typed or pasted.

The first version of the button crashed the process. `dialog.FileDialog.Resize` was
called before `Show`, and in Fyne 2.8.1 that path asks a dialog with no window yet for
its minimum size and dereferences nil — so the one interaction the button exists for took
the window down with it. It is fixed by showing first and resizing after, and pinned by a
test that drives the real widget under Fyne's test driver.

This adds no operation. Directory encryption is still the scan (`enc --all` on the
command line, the Encrypt section in the window), which flags credential-shaped files
rather than taking a tree wholesale; the folder chooser feeds that scan and does not
change what it does. CLI/GUI parity is therefore unaffected.

## Phase 4 — Code quality

The five call sites share one helper rather than each assembling an entry and a button:
`withBrowse` lays the pair out, `browseButton` opens the chooser, `pickerStart` decides
where it opens. No duplication introduced, nothing dead left behind.

---

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck` (Go 1.25.12) — code affected by 0 vulnerabilities.
  No dependency moved in this release.
- **Untrusted input**: a chosen path is untrusted in exactly the way a typed one is, and
  goes through the same core calls, which expand a leading `~`, refuse to create anything
  under a bare-tilde component, and confine extraction beneath its destination. The
  chooser adds no path that bypasses those.
- **Descriptors**: the file chooser returns an open `URIReadCloser`. It is closed
  immediately and only the path kept, rather than held open for the life of the dialog.
- **Secrets**: no passphrase or store content reaches the new code, no logging added,
  nothing committed. Screenshots are captured against a throwaway store under a
  redirected `HOME`, so no real path or listing is in the images.

---

## Phase 5.5 — Release safety

Rollback is `git revert` plus a rebuild. Additive and GUI-only: no store is written
differently, so a 0.2.1 binary reads a 0.2.2 store and the reverse. Publishing raises the
store's version floor to 0.2.2, which is the one effect not reversible from inside the
tool — machines running older binaries are refused until they install from the store.

---

## Limitations

- On Linux outside Flatpak, Fyne draws its own chooser rather than handing off to the
  desktop's. It is themed by angou, not by KDE or GNOME, and shows Fyne's own hidden-file
  toggle. Under Flatpak it uses the xdg portal instead.
- No test clicks through a whole selection: the regression test asserts the chooser opens
  and does not crash, not that choosing a file fills the field. That was verified by hand.
- The GUI's overall exposure is unchanged: far less use than the CLI.
