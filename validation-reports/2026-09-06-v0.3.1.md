# Validation report — angou v0.3.1

**Date**: 2026-09-06
**Spec**: none; a defect found by using the tool.
**Scope**: column alignment in the CLI's coloured listings. No GUI, container format, key
model, or store layout change.

---

## Summary

`ls` was laid out with `text/tabwriter`, which counts every rune in a cell towards the
column width. An ANSI escape is several runes and occupies no screen columns, so each
coloured cell was measured about ten characters wider than it looked and the columns did
not line up — in the mode the listing is normally read in. Uncoloured output, which is
what the e2e suite asserts and what a pipe receives, was correct throughout, which is why
no test caught it.

The listings are now laid out by `internal/cli/table.go`, which keeps the escape sequences
beside the text rather than inside it, so a column's width is measured from the text
alone. Widths are measured in screen columns via `go-runewidth` rather than in runes,
which also fixes a case tabwriter never handled: a stored path holding a double-width
character pulled the rest of its row left.

A second defect surfaced during the fix and is included: the totals line, being one or two
cells wide under a table of five, set the first column's width and stretched every row
above it to the width of "13 encrypted files". tabwriter had been ending a column block at
a line with fewer cells, which concealed it. Widths are now measured per section, with a
blank line ending a section.

## Phase 3 — Tests

| Gate | Result |
|---|---|
| `make test` (unit, `-race`) | pass — 9 packages |
| `make e2e` | pass |
| `make lint` (`golangci-lint` v2.12.2) | 0 issues |
| `shellcheck install.sh` | clean |

New coverage in `internal/cli/table_test.go`. The load-bearing one asserts the defect
directly: coloured output with the escapes stripped must be byte-identical to uncoloured
output, so colour cannot change the layout again. Alongside it: columns align, short rows
leave no trailing spaces, a totals line does not stretch the body, and a double-width
character is measured at two columns.

Verified by hand against a real store in `ls` and `ls --raw`, in colour and plain, since
what was wrong was how the output looks and no test reads a terminal.

Not run: `make e2e-container` (bootstrap path unchanged).

## Phase 4 — Code quality

Three call sites — `ls`, `ls --raw`, and the `enc --dry-run` scan report — shared the same
tabwriter-plus-`paint` pattern and now share one table type. `doctor` still uses tabwriter
because it emits no colour, so nothing was changed there to no purpose.

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck` (Go 1.25.12) — code affected by 0 vulnerabilities.
- **New dependency**: `github.com/mattn/go-runewidth v0.0.24`, promoted from indirect to
  direct. It was already in the module graph for the desktop GUI, so this adds an edge
  rather than new supply-chain surface. Pure Go, no cgo, so the static CLI stays static.
  Measured cost to the recovery binary: 7,430,144 → 7,479,458 bytes (+49 KB, +0.7%).
- **Output only**: the change is presentation. No path, secret, or store content is
  handled differently, and nothing new is written anywhere.
- **Secrets**: none in the changed code; the listing prints what `ls` already printed.

---

## Phase 5.5 — Release safety

Rollback is `git revert` plus a rebuild. Presentation-only: no store is written
differently, so a 0.3.0 binary and a 0.3.1 binary read the same store.

Publishing raises the store's floor to 0.3.1, which is the one effect not reversible from
inside the tool.

---

## Limitations

- **The README screenshots still show 0.3.0 in the title bar.** Nothing else in the window
  differs — this release changes no GUI code — so they were not re-captured.
- No test reads a real terminal. The tests assert the rendered strings; that the result
  looks right in a terminal was checked by hand.
- Width is now correct for double-width characters but still assumes a terminal that
  agrees with the Unicode width tables, which not every terminal and font does.
- `make e2e-container` was not re-run.
