# Validation report — angou v0.4.0

**Date**: 2026-09-07
**Spec**: `specs/003-macos-support.md` (macOS support).
**Scope**: macOS becomes a supported platform — Keychain backend, working agent,
`.app` packaging, and a macOS path through the installer. Every change is behind a
`darwin` build constraint or a `uname` branch; Linux behaviour is unchanged. Also a
patch-level Go toolchain bump (go1.25.12 → go1.25.13) to clear newly-disclosed stdlib
CVEs.

---

## Summary

Before this release the CLI and GUI compiled on macOS but were not usable there: the
keyring was a stub (`Open` returned `ErrUnavailable`), the agent refused every connection
because it authenticated peers with the Linux-only `SO_PEERCRED`, and `make e2e` did not
even compile (`keyring.BackendEnv` was Linux-only). This release makes macOS a real
target.

- **Keychain backend** (`keyring_darwin.go`, `darwin && cgo`) over `keybase/go-keychain`:
  a generic-password item in the login keychain, keyed by service `angou` and a per-store
  account, add-or-update on `Set`. The macOS CLI is built with CGO to link
  Security.framework — a macOS-only relaxation of the CGO-free rule, which is a Linux
  property (a `CGO_ENABLED=0` binary links libSystem on macOS regardless). Spec 001 R6.2
  and spec 002 R1.3 are amended in place. A CGO-free darwin stub keeps
  cross-compilation from a Linux box building a recovery-capable CLI.
- **Agent** (`peer_darwin.go`): peer authentication via `LOCAL_PEERCRED`, memory locked
  with `mlock`. Both are pure `x/sys`, so the agent works even in the CGO-free static
  build.
- **`BackendNone` ("none")**: a cross-platform "disable the keyring" knob, and the
  platform-independent no-keyring gate the e2e harness needs (the dead-D-Bus trick does
  not reach the Keychain).
- **Packaging**: `make build-app` assembles `angou-gui.app` with a generated `Info.plist`
  (version, commit, and the `.angou` UTI) and an `.icns` rendered from the SVG by
  `tools/svg2png` (oksvg/rasterx) and assembled with `iconutil`. `install.sh` /
  `uninstall.sh` branch on `uname`.

The icon rasteriser replaced a first attempt that used `qlmanage`, which produces a Quick
Look thumbnail — it drew the logo at roughly its native 64px in a 1024px canvas, so the
app icon came out about 15% of the tile. Rendering the vector to fill the target (the same
oksvg/rasterx stack fyne uses for the in-app icon) puts the logo at ~72% of the canvas,
centred, matching the window icon. Verified by eye at 512px.

- **Appearance**: two colour schemes, `macOS Light` and `macOS Dark`, styled after Tahoe's
  Liquid Glass (Apple's system palette plus rounder corners and airier padding, carried by
  two new per-palette metrics). macOS defaults to the one matching the system light/dark
  setting on a first run; Linux is unchanged. These are cosmetic and GUI-only, so no CLI
  parity applies (parity is about operations, not appearance). Not screenshotted for this
  report: `screencapture` is blocked by the Screen Recording permission in the environment
  the gates ran in; the schemes were verified to build, pass the GUI tests, and lint clean,
  and the colours are Apple's documented system values.

## Phase 3 — Tests

| Gate | Result |
|---|---|
| `make test` (unit, `-race`) | pass — 10 packages |
| `make e2e` | pass — 142 pass, 2 skip, 0 fail |
| `make lint` (`golangci-lint` v2.12.2) | 0 issues |
| `shellcheck install.sh uninstall.sh tools/*.sh` | clean |

Run on darwin/arm64 with the pinned toolchain (go1.25.13).

New coverage:
- `internal/keyring/keychain_darwin_test.go` (`darwin && cgo`): the Keychain round trip
  (set / get / replace / remove / not-found) and the `BackendNone` disable, in-process
  against a per-run throwaway service namespace so it never touches angou's own items and
  cleans up after itself. It is a unit test rather than an e2e one because the e2e harness
  redirects `HOME` for store isolation, and the macOS login keychain lives under `HOME`,
  so a child process finds no keychain and macOS raises "keychain not found" dialogs;
  go-keychain cannot target a separate keychain file to avoid that.
- The agent e2e tests now exercise the real `LOCAL_PEERCRED` path on darwin.

The two e2e skips are intentional and stated in the tests: `TestStaticBinaryHasNo­Dynamic­Dependencies` (the darwin CLI links Security.framework and is deliberately not
static — the R6.2 amendment) and `TestBareMachineAlsoInstallsTheGUIWhenPresent` (it
asserts the freedesktop `.desktop` install; macOS packaging is the `.app`).

Verified by hand on macOS: `init --generate` then `enc` / `ls` / `dec` with no passphrase
source (the Keychain unlocked the store), `doctor` reporting `keyring: reachable` and
`entry: present`, and `bootstrap --forget` reverting. A real `install.sh` / `uninstall.sh`
cycle placed the CLI in `~/.local/bin` and the `.app` in `~/Applications`, and removed
both, leaving no residue. The `.app` launches from Finder/Dock and quits cleanly.

Not run: `make e2e-container` (the Linux bare-machine bootstrap path is unchanged) and
`make e2e-keyring` (Linux KWallet, interactive).

## Phase 4 — Code quality

The platform split is by build constraint, so each backend is its own file rather than a
branch inside a shared one: `peer_darwin.go` mirrors `peer_linux.go`, `memory_darwin.go`
mirrors `memory_linux.go`, and the keyring gains `keyring_darwin.go` (cgo) plus a
`keyring_darwin_nocgo.go` stub. The backend-selection constants moved from the Linux-only
file to the platform-neutral `keyring.go` so both platforms and the shared harness resolve
them. The e2e platform-hardcoding was factored into `hostPlatform()` /
`otherReleasedPlatform()` helpers rather than repeated. The `.icns` and `.app` assembly
live in two small `tools/` scripts, not inline in the Makefile.

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck` (go1.25.13) — code affected by **0** vulnerabilities.
  Before the toolchain bump the same scan found 5 stdlib CVEs (net/http, x/net/idna)
  reachable through the GUI's initialisation, disclosed since 0.3.1 and fixed in
  go1.25.13; bumping `go.mod`'s toolchain from go1.25.12 to go1.25.13 clears them. Four
  advisories remain in required modules that the code does not call.
- **New dependency**: `github.com/keybase/go-keychain v0.0.1`, direct. It is the cgo
  binding to Security.framework and is compiled only into the darwin CLI; the Linux CLI
  does not import it and stays CGO-free. No transitive additions of note.
- **Promoted, not added**: `github.com/srwiley/oksvg` and `github.com/srwiley/rasterx`
  moved from indirect to direct for the `tools/svg2png` icon rasteriser. They were already
  in the module graph — fyne draws with them — so this adds no supply-chain surface, and
  neither is imported by the CLI.
- **Secrets**: the Keychain backend zeroes nothing extra because it copies nothing extra —
  the unlock secret is zeroed by the shared core, as on Linux. Keychain errors name the
  operation, never the value. The no-subprocess rule holds: the backend calls
  Security.framework directly and never shells out to `/usr/bin/security`.
- **Peer authentication**: the darwin agent authenticates the connecting peer's uid
  against its own via `LOCAL_PEERCRED` and refuses a mismatch, matching the Linux
  guarantee; the 0600 socket mode remains as a second control.
- **Test isolation**: the keychain unit test writes only under a per-run throwaway service
  namespace and removes it; a killed run leaves an inert entry under a random name, never
  touching angou's real items. Confirmed no `angou` entries and no `~/.local/share/angou`
  residue remained after the run.

## Phase 5.5 — Release safety

Rollback is `git revert` of the range plus a rebuild; nothing changes the store's on-disk
format, so a 0.3.1 binary and a 0.4.0 binary read the same store. The macOS additions are
inert on Linux (build-constrained out), and the Linux additions (`BackendNone`, the
constant move) are behaviour-preserving.

The toolchain bump is reversible by reverting the one line in `go.mod`. Publishing raises
the store's floor to 0.4.0, which is the one effect not reversible from inside the tool.

## Limitations

- **The macOS `.app` is not code-signed or notarized.** Opening it on a machine other than
  the one that built it raises Gatekeeper; the README says so and how to clear it. Signing
  is a later spec.
- **Double-clicking a `.angou` file launches angou-gui but does not open that blob.** The
  UTI gives the file angou's icon and angou-gui as its default app, but the GUI's model is
  the store, not a loose file, and no macOS open-file event is wired. Documented.
- **The memory pre-flight check does not run on macOS.** There is no cheap equivalent of
  the Linux MemAvailable/cgroup figures; documented in the README rather than guessed at.
- **`tools/screenshot.sh` is Linux/KDE-only** and exits on Darwin; the README screenshots
  are captured on Linux. The GUI is unchanged in this release, so the existing captures
  still match.
- **`make e2e-container` and `make e2e-keyring` were not run** (Linux-only paths,
  unchanged / interactive).
