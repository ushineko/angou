# Validation report — angou v0.2.0

**Date**: 2026-09-01
**Spec**: [002](../specs/002-desktop-gui.md), Status COMPLETE
**Scope**: a desktop GUI, the extraction of `internal/core` beneath both front ends, and
a scanner fix. No container format, key model, or store layout change.

---

## Summary

Three pieces of work, of which only the middle one touches code that already shipped.

The GUI is new and additive. It renders `internal/core` and holds no store logic of its
own, and a parity test fails the build if either front end grows an operation the other
lacks.

The core extraction is the risk in this release. Sixteen commands moved out of
`internal/cli`, which previously mixed orchestration with rendering — `doctor` wrote
into a `tabwriter` as it worked, so its findings did not exist as data at all. The claim
is that CLI behaviour is unchanged, and that claim is checked by comparison against a
built binary rather than by the suite alone.

The scanner now identifies a private key by its header rather than only by its name.

## Phase 3 — Tests

| Gate | Result |
|---|---|
| `make test` (unit, `-race`) | pass — 9 packages |
| `make e2e` | pass — 102 tests |
| `make e2e-keyring` | not re-run; the keyring code moved package but did not change |
| `make e2e-container` | not re-run; see Limitations |
| `make shellcheck` | pass |
| `tools/regress.sh` | no differences across 14 invocations |

New coverage: CLI/GUI operation parity; the `--verbose` route ordering, route naming and
the no-secrets-in-logs rule; the GUI keeping no passphrase-shaped struct field, and the
buffer wipe including the case where a short answer overwrites a longer one; private-key
detection by header, and the exclusions that stop it firing on public keys, prose and
certificates; the GUI artifact in the bootstrap namespace, the installer ignoring it when
selecting a platform, retention counting it separately from the CLI, and a bare machine
receiving the binary, desktop entry and icon.

Each new test was checked to fail with its fix removed rather than assumed to work. That
found one test that proved nothing: the installer test expected a platform listing that
only appears when the host platform's CLI is absent, so it passed with the bug present.

`tools/regress.sh` exists because the suite was not sufficient evidence for this
refactor. The first slice reordered two `--verbose` lines — the store identity and index
lines moved after the bootstrap suggestion — and every test stayed green. Nothing asserts
verbose ordering, and the keyring-gated line involved never appears under `make e2e`,
which drops the session bus on purpose. Only a byte comparison against a binary built
before the change caught it.

## Phase 4 — Code quality

`internal/cli` no longer imports `internal/keyring` or `internal/localkey`. What it still
names from the other packages is constants and types used to render output; every
operation goes through a `core.Session`, so the rule that neither front end assembles an
operation out of store internals is held by the compiler rather than by convention.

Duplication removed: the GUI's copy of the unlock-route enum, which had already drifted
in wording from the one in `internal/core`; a second definition of `BootstrapScriptName`;
and a third copy of the application icon.

One bug was found during release preparation and fixed here: `angou-gui --version` printed
seven Fyne errors before its answer, because the flag help lists the section names and
building a section constructed a theme icon before an app existed. The navigation's names
and order now live apart from its icons, and `sections()` is derived from that list rather
than repeating it.

`golangci-lint` v2.12.2: 0 issues.

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck@v1.1.4` — no vulnerabilities. Two remain in required
  but uncalled modules. Adding Fyne pulled in four reachable TIFF vulnerabilities in
  `golang.org/x/image@v0.24.0` (GO-2026-5066, -5062, -5032, GO-2026-4815), fixed by
  upgrading to v0.43.0 during the pass. That is the ongoing cost of the toolkit: the GUI
  has a dependency graph the CLI does not, and it needs scanning on its own account.
- **Secrets**: none committed. No key material, store, or `.asc` file is tracked. Four
  PEM header strings appear in `internal/core/scan_test.go`; they are headers with no key
  bodies, present because a header detector cannot be tested without one, and they
  decrypt nothing.
- **Subprocesses**: still none. Neither `internal/gui` nor `internal/core` calls
  `exec.Command`; the cursor-theme shim reads config files directly rather than calling
  `gsettings`, and the GUI makes no network calls.
- **Secret handling**: passphrases are borrowed and zeroed; the GUI keeps no session
  between operations, and a source-scanning test fails if its types grow a field that
  looks like somewhere to keep one. Memory hygiene is documented as weaker in the GUI
  than in the CLI — text typed into a widget is a Go string and cannot be overwritten —
  in About and in the README rather than left implied.

## Phase 5.5 — Release safety

Rollback is `git revert` plus a rebuild. The GUI is additive: dropping `cmd/angou-gui`
leaves the CLI untouched. The core extraction is the one change to shipped code, and it
is behaviour-preserving by the evidence above.

The store is not migrated and the container format is unchanged, so a 0.1.x binary reads
a 0.2.0 store and the reverse. What is not reversible from inside the tool is the version
floor: publishing raises it, after which older binaries are refused wherever the store
syncs.

## Limitations

Stated rather than left to be discovered:

- **The GUI has had far less use than the CLI.** Every bug found during this work was
  found by using the window, and two of them were caused by earlier fixes in the same
  pass — the flag that stopped an empty store reloading forever also stopped it reloading
  at all. The destructive paths — Remove, Prune, Forget, Rotate identity — are wired and
  confirmation-gated, and are the least exercised code in the project.
- **`make e2e-container` was not re-run for this release.** The bare-machine bootstrap
  path changed: the installer now also places a GUI, a desktop entry and an icon. That is
  covered by the e2e suite against a simulated bare machine, not in a container.
- **GUI interaction is not covered by automated tests.** The view models are tested
  headlessly and the operations are tested through the CLI, which runs the same core. No
  test clicks a button.
- **The GUI is stashed for the host platform only.** It needs CGO and cannot be
  cross-compiled, so a store carries the CLI for four platforms and the GUI for however
  many someone has built on.
