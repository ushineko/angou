# Validation report — angou v0.1.4

**Date**: 2026-09-01
**Spec**: [001](../specs/001-angou-format-keying-and-store.md), amended by R6.6.1
**Scope**: a package move with no behaviour change, and calibration of the credential
scan. No format, key model, or store layout change.

---

## Summary

Two pieces of work, both prompted by looking at what the code actually did rather than
at what it was supposed to do.

`lib/container` became `internal/container`. The public placement was justified in the
spec as "exported, third-party readable", and that justification does not survive
examination: R1.5 already guarantees third-party readability by a stronger route, since
stock `gpg` decrypts a blob body without angou. Every importer was inside this module.
What a public package adds is a commitment to keep every exported symbol, which nothing
had asked for.

The credential scan gained `--dry-run` and a great deal more scepticism, both driven by
running it against a real home directory.

New coverage: `--dry-run` reports and stores nothing, and is refused where it would mean
nothing; templates, prose and programs are declined; content verification for key
extensions and for the name-mentions rule, including binary content.

The scanner's judgement is now a table of cases taken from real data, named for what
they are: `secrets.py`, `libssh2_userauth_password.3`, `absl_cordz_sample_token.pc`,
`KDB4_PasswordsOnly.xsl`, `secret-report.yml`, session handles ending in `.key`. Each
was actually offered by the previous version. A future change to these rules has to
argue with them by name rather than merely keep a count green.

## Phase 4 — Code quality

`make lint` reports 0 issues. The package move is mechanical; `go list` shows fourteen
packages, all under `cmd/` or `internal/`, and the compiler now enforces what the `lib/`
convention only suggested.

## Phase 5 — Security review

**Dependency scan.** `govulncheck`: no vulnerabilities. No dependency changes.

**Reduced public surface.** Moving the container package into `internal/` removes the
only exported API this module had. That is a small security benefit and a larger
maintenance one: an exported parser is a surface that must keep its behaviour stable for
callers we cannot see.

**The scan reads file contents now.** It reads at most the first 512 bytes of a
candidate, to tell a private key from a certificate and a credential from a note about
credentials. It reports rather than acts, it does not follow symlinks, and `--dry-run`
performs the same reads while storing nothing. Reading a file to decide whether to offer
it is proportionate to a command whose purpose is to find files worth encrypting.

**Fewer false positives is a security property, not only an ergonomic one.** A scan that
offers 140 files, most of them Python's standard library, trains the user to accept
without reading. The value of the per-file question depends entirely on the list being
short enough to think about.

**Honest reporting retained.** An empty or short result is still reported as what the
scan found, never as an assurance that nothing sensitive is present.

## Phase 5.5 — Release safety

**Rollback**: revert the release commit. No format or store change; a store written by
any 0.1.x is readable by any other.

**Migration**: none. The package move is internal to the module and invisible to a user.
An external importer of `lib/container` would break, which is why it was done now rather
than later; the package was public for one day across three tags and cannot plausibly
have been adopted.

**Behaviour change**: the scan offers fewer files. Someone relying on the previous
output would now see less — which is the intent, and `--dry-run` shows exactly what
changed.

## Known gaps

- The scanner's rules remain a judgement call calibrated against one machine. They will
  need revisiting on a different one, which is what `--dry-run` is for.
- gnome-keyring remains untested (carried from 0.1.2).
- `make e2e-container` is a target with no implementation.
- The macOS Keychain backend is deferred; the desktop navigator is not started.
