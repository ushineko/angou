# Validation report — angou v0.2.1

**Date**: 2026-09-01
**Spec**: [002](../specs/002-desktop-gui.md), amended by R5D
**Scope**: three fixes to the release and path handling. No container format, key model,
or store layout change.

---

## Summary

Every fix here came from publishing 0.2.0 to a real store and bootstrapping a second
machine from it. None was found by the test suite, and one of them the suite could not
have found, because it was a bug about the relationship between an artifact and the
description signed beside it.

`angou release` recorded the version and commit of the tool doing the stashing rather
than of the artifact. A stale `dist/` was therefore signed under the current version:
the store held `angou-linux-amd64-0.2.0` whose bytes reported 0.1.4, and the machine
that installed it was refused by the version floor the same publish had raised. The
signature was valid the whole time.

The other two are about paths a human types. A quoted `~` reached angou literally and
created a store in a directory named `~` — and that directory is a trap, because the
obvious way to remove it expands to the user's home directory.

## Phase 3 — Tests

| Gate | Result |
|---|---|
| `make test` (unit, `-race`) | pass — 9 packages |
| `make e2e` | pass |
| `make shellcheck` | pass |
| `tools/regress.sh` | no differences across 14 invocations |

New coverage: a binary from another build is refused and nothing is stashed; tilde
expansion, including the cases deliberately left alone (`~user`, `backup~`, `~store`,
`dir/~/file`); and the refusal to create anything under a bare-tilde component, with
ordinary tilde-containing filenames still permitted.

The e2e stand-in binaries were shell scripts, which the new guard correctly rejects.
They are now copies of the binary under test — a real Go build from the current commit —
which is a better fixture regardless: the previous ones could not have caught a
mislabelling bug because they carried no build identity to mislabel.

Two behaviours are reported rather than refused, and both were chosen deliberately. A
modified working tree makes a commit inexact, which is worth saying and is also the
normal state of a tree someone publishes a test release from. And a stashing binary with
no commit of its own says the check did not happen, rather than comparing against the
`unknown` placeholder and appearing to have checked.

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck@v1.1.4` — no vulnerabilities. Unchanged from 0.2.0;
  no dependency moved.
- **Supply chain**: this release is a supply-chain fix. A store could serve a signed
  artifact whose signed metadata described a different build, and both a bootstrap and a
  `doctor` report would have agreed with the metadata. The signature was never the weak
  point; the description beside it was, and nothing checked that it matched.
- **Path handling**: creating a directory named `~` is now refused. The hazard is that
  its natural cleanup command, `rm -rf ~`, expands to the user's home directory —
  verified in a shell rather than assumed.
- **Secrets**: none committed. No key material or store is tracked.

---

## Phase 5.5 — Release safety

Rollback is `git revert` plus a rebuild. No format or store change, so a 0.1.x binary
reads a 0.2.1 store and the reverse.

The version floor is the one thing not reversible from inside the tool. A store already
floored at 0.2.0 goes to 0.2.1 on publishing, and machines running anything older are
refused until they install from the store.

---

## Limitations

- **The 0.2.0 artifacts already published to a real store are mislabelled** and are not
  repaired by installing this version. They have to be removed from the store and
  replaced, and any machine that installed one has to install again.
- The GUI's exposure is unchanged from 0.2.0: far less use than the CLI, and no test
  clicks a button.
- `make e2e-container` was not re-run.
