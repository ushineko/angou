# Validation report — angou v0.3.0

**Date**: 2026-09-05
**Spec**: [002](../specs/002-desktop-gui.md) R5.9, R5.10, R6.2
**Scope**: the remembered store, shared by both front ends; the first-run rework; result
banners. No container format, key model, or store layout change.

---

## Summary

Three changes, all from using the tool rather than from reading the spec.

A machine that had been set up still needed `--store` or `$ANGOU_STORE` on every command,
while the window remembered a store in Fyne's preferences that the command line could not
see. They are one tool over one store, and having each front end remember its own was a
difference with nothing behind it. `init` and `bootstrap` now record the store in
`~/.config/angou/config.json`, both front ends read and write it, and `angou use` changes
it. `--store` still wins and `$ANGOU_STORE` wins over both, so a one-off against a backup
copy cannot become the default that the next `rm` runs against.

First-run setup offered only creation — one dialog headed "Set up angou" whose only button
was "Create the store". That is the wrong default for a store built to be synced: every
machine after the first meets angou with the store already on disk, and reaching it meant
cancelling the dialog and finding a header button. Opening a store is now the first and
selected path, and choosing it opens the store immediately, which is the passphrase
prompt, rather than deferring it to whenever a section is navigated to.

Result banners floated over the bottom of the content, which is where Store keeps Decrypt,
Extract, Rename and Remove: the banner covered the controls it was reporting on. They now
have a reserved region above the status bar that keeps its height whether or not a banner
is in it. They also lasted 1.6 seconds, long enough to notice and not long enough to read.

## Phase 3 — Tests

| Gate | Result |
|---|---|
| `make test` (unit, `-race`) | pass — 9 packages |
| `make e2e` | pass |
| `make lint` (`golangci-lint` v2.12.2) | 0 issues |
| `shellcheck install.sh` | clean |

New coverage:

- **e2e** (`tests/e2e/remember_test.go`): init records the store and `ls` finds it with
  `$ANGOU_STORE` removed from the child environment; a `--store` on one command does not
  change what is remembered; `use --forget` restores the error, and that error names the
  remedy; a directory holding no store is refused rather than remembered. The first also
  asserts the config file holds neither the passphrase nor the fingerprint, and is 0600.
- **unit** (`internal/core/config_test.go`): round-trip, tilde expansion, a corrupt file
  treated as "nothing remembered" rather than as a failure, and the file mode.
- **unit** (`internal/gui/firstrun_test.go`, `flash_test.go`): first run defaults to the
  open path and shows exactly one body at a time; failures do not clear themselves; a
  newer banner replaces an older one; a stale fade timer cannot empty the slot under the
  banner that replaced it.

The parity test caught the omission it exists for: `use` had no GUI affordance and the
build failed until the chooser was registered as its counterpart.

Not run: `make e2e-container` (bootstrap path unchanged).

## Phase 4 — Code quality

The store-resolution logic is in `internal/core` and both front ends call it; neither
reimplements it. The first-run dialog's contents are separated from the dialog so the path
swap is testable headlessly. `useStore` is shared by first-run and the header chooser, so
the two cannot disagree about what counts as a store.

---

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck` (Go 1.25.12) — code affected by 0 vulnerabilities. No
  dependency moved.
- **What the new file holds**: a store path, and the test asserts it holds neither the
  recovery passphrase nor the identity fingerprint. Written 0600 through a temporary file
  and a rename, under a 0700 directory. A path is not a secret — it is already in
  `$ANGOU_STORE`, in shell history, and in `doctor` output — but it says where the user
  keeps their credentials, which is not something to widen by default.
- **Precedence is the security-relevant part**: a remembered store must never override an
  explicit one, or a command aimed at one store would run against another. `--store` >
  `$ANGOU_STORE` > remembered, asserted by an e2e test rather than by reading the code.
- **Untrusted input**: the remembered path goes through `ExpandPath` like every other, so
  the tilde rules hold. A config that will not parse is treated as nothing remembered.
- **Secrets**: no passphrase reaches the new code. The GUI's first-run open path holds the
  passphrase only for the operation, through the same `guiSecrets` path as before.

---

## Phase 5.5 — Release safety

Rollback is `git revert` plus a rebuild. Nothing in a store changes. The config file is
additive: a 0.2.x binary ignores it and asks for `--store` as it always did, so a
downgrade loses the convenience and nothing else.

Publishing raises the store's version floor to 0.3.0, which is the one effect not
reversible from inside the tool: machines running older binaries are refused until they
install from the store.

---

## Limitations

- The GUI's first-run open path was exercised by hand on a machine that already holds a
  local key, so the passphrase prompt it now raises was not seen on a machine without one.
  The tests cover the dialog's structure, not that flow end to end.
- No test drives a click: the banner tests assert the slot's contents and the hold policy,
  not that a banner is legible where it now sits.
- The reserved banner region costs about 68px of window height at all times. That is a
  deliberate trade against covering the controls underneath, and it is visible in the
  screenshots.
- `make e2e-container` was not re-run.
